# Current AZSX feature contracts

This is the stable engineering inventory for the only supported client,
**official 0.138.0**. Rows describe contracts to preserve, not universal runtime
validation. Source behavior, a built DLL and a distributed archive are different
evidence scopes. Follow [testing](../development/TESTING.md) for evidence requirements and limits.

Do not delete or reuse an ID when a feature is disabled or absorbed by upstream;
record its current disposition. Native personal marks replace duplicate-loot
gold compensation. Reserved removed IDs are not reassigned.

## Review requirements

[AZSX-BEHAVIOR.md](AZSX-BEHAVIOR.md) expands every stable feature into individually
identified acceptance criteria, regression cases and evidence requirements. Keep
those current with semantic changes; this generated table remains the index.

A native compatibility change must account for AZSX-01 through AZSX-28, including
reserved removed IDs and upstream-native behavior. Record the
native boundary, exact source/artifact identity, checks and limitations. Preserve
producer/recipient GUIDs, host/private layouts, native ownership, reset and
reentry semantics. Matching hook prologues do not establish complete parity.

Use [testing](../development/TESTING.md) for relevant portable, Windows and Lua profiles.
Synthetic assessors and stand-ins do not establish gameplay or visible frames.
Exact-archive, normal-runtime and publication validation are deliberate
milestones, not implied by source cleanup.

See [Rust ownership](../development/RUST-ARCHITECTURE.md) and [active rules](../features/FEATURE-RULES.md).
Player-facing behavior and maturity are in [the feature guide](../player/FEATURES.md).
